# Human conversation review

The corpus and evaluation runner are implemented. **No real baseline/candidate outputs or completed human A/B review exist as part of this change.** Injected-provider checks establish execution, protocol validation, cost guards and bookkeeping. They do not establish that anyone preferred the dialogue or found it funny, flirty or memorable. All report ratings and baseline-comparison status begin **unrated**.

The corpus contains 60 individually authored eight-turn scripts: 12 each for Mira, Jules and Dev, 12 seeded Blind dates, and 12 attributed Double dates. Six additional 30-turn fixtures test corrections, ownership, notebook retention and an offstage pairing. Scripts and human-review checkpoints live in `src/restaurant/evaluation-fixtures.ts`. The runner uses production system, turn-note, transcript, persona-sheet and validation builders plus the production social and delivery controllers. It uses controlled dining snapshots; it does not run physics, course timers, speech recognition, synthesis, a browser or the complete transport.

1. **Freeze what is being compared.** The intended code baseline is `05ff06a5e5727fc99d78fe64469460ab286a4d0a`; the candidate must be an explicitly recorded committed revision. A report records `sourceRevision`, `sourceTreeDirty` and `corpusSha256`. Unknown provenance or a dirty source tree is exploratory evidence only. Compare the same selected scripts, corpus hash, model, upstream alias, response limits and delivery settings. Comparing Haiku against Sonnet within one revision is a model comparison, not the required old-code/new-code comparison. Preserve the complete JSON reports under distinct revision/model/batch filenames before another approved run overwrites `.qa/date-model-comparison.json`. Keep generated prompts and reports out of Git.

2. **Resolve the baseline bench blocker before calling this an A/B test.** The baseline does not expose all the new shared system/persona/Double-validator helpers, and it does not contain this corpus/runner. Merely running the old comparison command there would compare different fixtures and contracts. An isolated baseline bench needs a reviewed instrumentation-only backport of the identical corpus, capture/report runner and the necessary pure exports. It must retain the baseline's actual prompt text, note/transcript behavior, memory handling and response limits. Record the bench revision and instrumentation diff, and verify parity against baseline prompt fixtures. Do not backport candidate content or behavior and label it baseline. This bench has **not** been constructed or executed; until it is, the 70% code-preference gate is blocked, not passed. Do not automatically checkout, replace, deploy or reset either source tree to obtain it.

3. **Preview and select a batch without calls.** These commands are safe dry runs; they do not read credentials or write a report:

   ```sh
   pnpm compare:models
   pnpm compare:models --models haiku --scripts mira-fry-treaty,jules-awkward-silence,dev-bold-flirt
   pnpm compare:models --models horde --suite continuity
   ```

   The preview lists planned requests and first-turn reservations. Later request sizes depend on actual prior replies; each is separately reserved before calling. A budget can stop a script or leave later scripts unrun. Keep those omissions and provider/format failures visible in the review coverage table.

4. **Obtain operator approval for the actual provider, exact selection and explicit maximum spend before live capture.** No such live capture is authorized by this document. The examples below are deliberately commented out. A literal `--budget` is a technical requirement, not evidence of approval. A $0 budget permits only Horde; it still sends fictional prompts to volunteer hosts, who may inspect or retain them. There are no retries or paid fallbacks.

   ```sh
   # DISABLED until the operator explicitly approves this provider, script batch and $0.50 cap:
   # pnpm compare:models --models haiku --scripts mira-fry-treaty --run --budget .50
   # DISABLED until the operator explicitly approves this community-hosted capture:
   # pnpm compare:models --models horde --scripts mira-fry-treaty --run --budget 0
   ```

   Capture matched baseline and candidate batches only after the baseline bench is ready. Do not silently increase a cap to finish a corpus. Text cost is estimated from reported usage and configured rates, not a provider invoice; missing usage keeps the conservative reservation accounted. Reports retain exact fictional requests, raw responses, notebook snapshots, errors, first-text/first-complete-utterance latency, total response latency and per-model p50/p95 summaries. First utterance is not first audio, and this runner does not measure synthesis or end-to-end game latency.

5. **Prepare blind paired transcripts for two independent human reviewers.** A coordinator keeps the source-revision key, labels each pair A/B, and counterbalances baseline/candidate order across scripts. Use the same script/model pair on both sides. Remove source labels, model/provider names and timing/cost summaries from the initial quality review, and redact cast names when measuring cast identification. Preserve turn order, human words, speaker ownership and interruption markers; do not cherry-pick the best line or hide failed/missing turns. Seeded Blind dates should be judged against their actual seeded identity rather than the borrowed rig's preset biography. Use the 36 preset scripts for the anonymized preset-cast identification denominator; report Double speaker confusion separately.

6. **Record judgments before revealing the key.** For each script and reviewer record `A`, `B` or `tie`, a reason, any exact earned memorable line, and the 1–5 rubric ratings. For each candidate turn record whether it addresses the latest human message. Appropriate Double silence may preserve room for the friends; record why it is appropriate rather than automatically counting silence as success. Check each long fixture's `mustRecall` and `mustNotClaim` against the actual transcript and notebook at its specified turn. Mark invented facts, repeated stories, unheard callbacks, transferred couple facts/progress, pressure and false refusals explicitly. Reviewers work independently before discussing disagreements. Leave missing judgments null/unrated; a script that failed capture is not a completed favorable comparison.

7. **Compute the approved gates from real review rows.** Candidate preference is candidate wins divided by baseline wins plus candidate wins, excluding ties; report both reviewers' counts, pooled non-tied counts, ties and capture coverage. The target is at least **70%** candidate preference, at least **90%** latest-turn relevance, at least **80%** anonymized preset-cast identification, and **both reviewers** finding an earned memorable beat in at least **40 of the 60** short scripts. Report continuity failures and serious invented/unheard/cross-couple facts separately; averages cannot erase them. Publish numerator, denominator, excluded/missing cases and actual quoted evidence. These are review gates, not a guarantee that a clip or game will go viral.

8. **Keep qualitative and technical evidence separate.** Provider-disabled CI can pass protocol, timeout, receipt, snapshot and browser regression checks and upload screenshots. It cannot pass human preference, cast recognition, voice acting, physical-phone usability or internet/NAT quality. Update the review manifest with the two report filenames/hashes, source revisions, corpus hash, models/settings, reviewer rows, computed gate results and unresolved blockers. Only then can baseline comparison move from unrated to a documented human result. Deployment remains a separate authorized step with its existing packaging, live-configuration preservation and asset-verification requirements.
